# RX appended FCS ownership, 2026-10-16

Full-port coverage: COV-RTL-014 (RX) and COV-RTL-009 (security).
Base: `14895609087d6cd7de30f77d60582affc1661598`, WIP branch
`wip/hp-rtl-runtime-48-merge-20261010`. Full WLAN acceptance stays OPEN.

## Reference and cause

- [Frozen Linux reg.h](https://github.com/torvalds/linux/blob/fd179f8a05be3ccae366b9b96e176b51fbe54aab/drivers/net/wireless/realtek/rtlwifi/rtl8723be/reg.h)
  defines RCR_APPFCS as bit 31. Production RCR default `0xf0007a0e`
  includes this bit.
- [Frozen Linux PCI RX](https://github.com/torvalds/linux/blob/fd179f8a05be3ccae366b9b96e176b51fbe54aab/drivers/net/wireless/realtek/rtlwifi/pci.c)
  forwards normal RX with FCS to mac80211; C2H takes a separate route.
- [Frozen NetBSD ieee80211_input](https://github.com/NetBSD/src/blob/03d918f6d0e81fa05b8f1160eca0628ad39988a6/sys/net80211/ieee80211_input.c#L526)
  removes the four CRC bytes before crypto/decapsulation only when
  `m->m_flags & M_HASFCS`. The project's copied RX mbuf lacked this flag.
- NetBSD's PCI if_rtwn does not enable APPFCS in its RCR setup;
  copying its input call without accounting for this hardware policy
  difference lost the FCS contract. This is a source-established adapter
  defect; no observed HP WPA2 failure is attributed to it without testing.

## Change and checks

After successful `m_devget`, mark the copied mbuf `M_HASFCS` when the
current cached receive configuration has APPFCS set. Preserve frame bytes,
descriptor length, DMA ownership, C2H routing and the stack's sole trimming
ownership. When APPFCS is clear, do not mark or trim the packet.
